# Interview session loop

Playbook for `interview-prep-practice`. Extend this file when the pattern changes.

## Inputs

- One track: data structures, algorithms, system design, Kotlin or Android, or behavioral
- A problem the user is allowed to practice
- The session length, or the default below

## Steps

1. If the track is not already chosen, ask for one. One track per session.
2. Pick one problem at the agreed difficulty. State the time box before starting. Default to 25 minutes for a coding problem and 20 minutes for a design prompt.
3. Work in this order: restate the prompt, give a brute-force idea, then a better approach, then code or a structured design. Stop when the time box ends.
4. Review correctness, complexity, and one cleaner alternative. Run the solution against a few cases when a runner is available.
5. Write four lines: the problem, the outcome (solved, partial, or stuck), the mistake or gap, and the next topic to drill.
6. Do not store company-confidential interview content. Use original prompts or problems the user already has rights to practice.

## Anti-patterns

- Switching tracks mid-session
- Continuing past the time box to "finish the optimal solution"
- Saving a prompt from a company interview that was not released for practice
- Writing a long postmortem instead of the four-line log
